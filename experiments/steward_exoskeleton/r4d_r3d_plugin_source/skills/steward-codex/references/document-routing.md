# Document routing

Use this reference after `steward-codex` has routed a current local document task to `steward_read_document`. Choose the action from the requested outcome, not from a preferred parser.

| User outcome | Action | Native location to preserve |
|---|---|---|
| Answer or summarize a focused factual question | `EVIDENCE` | PDF page/block, EPUB or DOCX section/block, XLSX sheet/cell/table, PPTX slide/shape/table, image page/region |
| Compare or synthesize the same focused question across several existing local documents | `EVIDENCE_SET` | Preserve every file's current SHA-256, packet digest, native location, citation, status, unknowns and omissions separately |
| List headings, chapters, slides, sheets or document structure | `STRUCTURE` | Section, slide, sheet and graph node identities |
| Find occurrences without publishing surrounding facts | `LOCATE` | Match count, match mode and native location |
| Read broadly when no focused query can represent the task | `READ` | Every returned item location plus pagination |
| Extract table values or workbook cells | `EXTRACT_TABLE` | Table identity, sheet, cell, row and column |
| Extract formulas | `EXTRACT_FORMULA` | Formula node or workbook cell; for XLSX preserve the raw unevaluated formula and structured references |
| Inspect appearance, chart, figure, layout, scan or slide | `VIEW` | Page/slide/sheet/node, crop and artifact digest |

For PDF, use page locations and bounded page continuations; preserve `PDF_OUTLINE`, `PDF_ANNOTATION`, `PDF_FORM_FIELD` and repair diagnostics when returned. For EPUB, retain the observed section number and heading path, preserve tolerant-HTML fallback warnings, and do not invent printed page numbers. For DOCX, retain section/block or table row/column and distinguish `WORD_COMMENT`, `WORD_FOOTNOTE`, `WORD_ENDNOTE` and `WORD_REVISION`. For XLSX, distinguish displayed values, raw unevaluated formulas, structured references, comments, sheets, merged ranges, hidden rows/columns, tables and `WORKBOOK_CHART` source references. For PPTX, retain slide, shape reading order, table coordinates, `PRESENTATION_SPEAKER_NOTES`, accessibility text and cached chart data; do not count a shape container as duplicate visible text. For PNG, JPEG and TIFF, use OCR facts only when the execution trace identifies the OCR backend, use `VIEW` when typography, layout or imagery matters, and preserve decoder projection/subsampling facts when returned.

PDF `STRUCTURE` is a native outline/metadata operation and deliberately does not parse page bodies or scan page annotations/forms. `PDF_NATIVE_STRUCTURE_BODY_NOT_PARSED` is its boundedness statement, not a content failure. `PDF_NATIVE_STRUCTURE_OUTLINE_ABSENT` means the file exposes no native bookmark hierarchy; report `ROOT_METADATA_ONLY` and do not infer headings. A failed native structure operation does not fall back to body parsing. A timed-out `EVIDENCE` call must not be followed automatically by broad `STRUCTURE`; preserve the timeout and use one shortest distinctive literal term in a fresh focused `EVIDENCE` request only when the user's task still needs that evidence.

For a large PDF, EPUB, DOCX, XLSX or PPTX, prefer `EVIDENCE` with the shortest distinctive source term. The service stream-stages and hashes the source, then scans pages or native package containers without retaining the complete source or complete parsed graph in Python memory. Preserve `resource_usage.admission_profile`, source/expanded limits, stage elapsed times, parser deadline, and a `MAP` execution profile when returned. The native operation deadline encloses the adaptive parser ceiling plus admission/release grace, so do not duplicate a timed-out call automatically. Use broad `READ` only when the task genuinely requires a broad graph and accept its explicit normalized-output bound.

The execution trace owns escalation. A complete query-relevant native container with sufficient observable text or structure should not be reparsed. A missing match or insufficient container may trigger the bounded deeper profile. PDF MAP already applies page-local OCR to low-text pages and therefore must not be followed by a duplicate whole-document OCR retry; focused small PDF/image evidence may use quality-gated local OCR. Optional auxiliary-component warnings preserve other valid content and do not prove whole-document corruption. Do not manually retry a different backend after a sufficient result, and do not describe lexical normalization as semantic matching.

For scan-heavy PDFs, focused `EVIDENCE`/`LOCATE` uses page-local RapidOCR only on pages without a usable embedded text layer; broad `READ` uses the bounded `STEWARDPageOCR` line projection. Preserve page/line locations, OCR engine/version, confidence or region facts when returned, pagination, and `MODEL_DERIVED`/`OCR_MODEL_APPROXIMATE`. OCR text is searchable cited observation, not guaranteed verbatim source text. Do not replace a successful page-local projection with whole-document Docling OCR.

Single-document `EVIDENCE` publishes packet v3 with an `EVIDENCE_SUMMARY` execution projection. Treat `facts` as the unique cited native nodes and `slices` as their query-window relationships: zero-based `fact_indexes` reference `facts`, and `anchor_fact_index` plus `anchor_citation_id` identify the anchor without duplicating its fact object. Do not request a second call merely to recover omitted parser inventories; use a continuation only for material omitted evidence.

Leave `diagnostic_detail` at `COMPACT` for ordinary answers. Use `FULL` only for explicit parser/resource diagnosis; it adds the complete execution trace and resource accounting without changing evidence selection or citations.

For `EVIDENCE_SET`, use the shortest filename/path query that deterministically represents the requested set and one focused `content_query` shared by all candidates. Use current discovery unless the user asks to use a verified historical inventory as the candidate baseline; a Snapshot is never current-content authority. Process the returned continuation only when the remaining documents matter. A candidate-set or request mismatch is a safe stop, not permission to reconstruct an index manually. Preserve each item failure alongside successful siblings and never convert missing evidence in one file into a corpus-wide negative claim.
